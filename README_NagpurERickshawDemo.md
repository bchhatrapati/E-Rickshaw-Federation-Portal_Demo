# Nagpur E-Rickshaw Federation Demo

## Install the extra dependency

```bash
npm install qrcode.react
```

The project should already have `react`, `lucide-react`, and Tailwind CSS installed because the supplied component uses them.

## Use the component

- Next.js App Router: place the component in `app/page.jsx` (or import it from there).
- Vite/React: use it as `src/App.jsx`.

The file is a client component and starts with `"use client"` for Next.js compatibility.

## What works in this prototype

- Four clickable workflows: federation dashboard, member portal, member ID/receipt, and public QR record lookup.
- Fictional Nagpur sample records with dynamic dashboard calculations.
- Browser-local demo registration and payment-state changes.
- CSV download, print dialog, telephone link (only after a real number is configured), and a prefilled WhatsApp draft.
- Standards-compliant QR image generated by `qrcode.react`; it opens this deployed app with `?verify=MEMBER_ID`.

## Prototype limits to disclose

- All member data is fictional. Do not enter real member records or personal information in this prototype.
- Changes are stored in the current browser's `localStorage`; there is no shared server/database.
- The member PIN `1234` is a demonstration shortcut, not secure authentication.
- Recording a payment only changes demo figures; no money is collected and no payment gateway is connected.
- Document status is sample/manual data; no Parivahan or RTO API is connected.
- WhatsApp opens a prefilled draft; the user must review and press Send.
- QR lookup works across phones for the seeded sample records when the app is deployed over HTTPS. A member added in one browser will not exist on another phone until a shared backend is built.
- ₹100 is a placeholder membership fee and must be confirmed with the federation.
- Nagpur RTO codes are verified; sample stand/zone names and all demo records must be confirmed or replaced by the federation.
